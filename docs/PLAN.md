# cs-tool-x 产品与实施规划

日期：2026-11-13。当前产品名、仓库名为 `cs-tool-x`。发布标识 `cc.anjing.cs-tool-x` 从首个可更新版本开始保持稳定；以后可调整显示名称，不能随意变更更新身份。

## 目标

以一个极简、响应快的 macOS 客户端，逐步承接传统开发工具中最常用的工作流程：服务器连接与终端、文件传输、数据库操作、接口调试及开发辅助。每个模块有适合自己的操作入口，共享连接与环境概念、凭据存储、任务状态和更新流程。

功能覆盖按真实使用决定。第一阶段不追求所有传统工具的完整功能，不引入外部插件市场、账号系统或默认云同步。

## 使用方式

整个窗口复用 FinanceX / EnglishX 的无标题栏原生框体，顶部空白可拖动和双击最大化，保留原生缩放及快捷键。首页展示 Shell、数据、Git 三张独立卡片，沿用 FinanceX 的卡片结构与大留白，配色统一为原 ShellX 的暖纸张、低饱和绿蓝与浅色分隔线。进入后各模块拥有自己的完整界面与返回首页入口；Cmd+1 返回首页。接口与工具等能力按实际需求逐步加入。Shell 借鉴 anjing-shell 已打磨的分组、搜索、标签和分屏交互，使用真实 PTY 替换 mock，不导入示例服务器与假日志。数据模块内部继续区分 SQL、ES、Redis。连接到某个环境不自动启动其他模块，也不在启动时扫描数据库或服务器。

“集成到一个客户端”包括入口一致、连接信息可复用、环境和风险状态可见、相关任务可串联。模块内部仍保留 SQL 会话、PTY、SFTP 传输等不同生命周期。

## 性能约束

- 原生 UI 主线程只处理界面与轻量状态；网络、协议解析、大结果整理移出主线程。
- 数据进程首次连接时启动，最后一个数据会话关闭后停止。SQL 池每连接最多 2；首版最多同时 4 个数据会话。
- 结果最多 500 行，SQL 单元格展示约 64 KiB、显示负载约 8 MiB，ES 响应体 8 MiB 硬上限；RPC 请求 256 KiB、响应 16 MiB、最多 4 个引擎任务。驱动接收巨大单值的峰值仍需真实验证。
- 终端仅在用户打开会话后创建 PTY，最多 4 个标签、每个标签 2 个分屏、每个终端历史 2,000 行，不自动录制。切换工作区保留用户打开的会话；断开与退出释放进程和句柄。
- 依赖升级锁定版本和 lockfile；不用“用了 Rust / 原生界面”替代性能证据。

拟验证目标：本机 release 冷启动 2 秒内、普通界面交互 p95 100 ms 内、500 行滚动无明显停顿。测量同时记录机器、版本、数据量、网络、冷/热状态；连接/数据库执行与 UI 开销分开。目标尚未构成实测结论。

## 凭据和环境

连接元数据写入 Application Support 下专用目录；配置权限 0600。数据库密码/API Key 可选择保存在本机 data-credentials.json（0600，不留备份），或只在本次会话内存中。SSH 密码按用户选择可明文保存到本机 shell.json，编辑界面直接显示；不会进入公开源码或发布包。不使用钥匙串。SSH 私钥内容不导入应用，由系统 ssh/Agent 管理。对新主机指纹不静默接受。未来共享隧道必须显式建立、绑定回环地址，记录引用并在最后使用者退出后关闭。

生产环境明显标记。数据写入、远程命令和文件覆盖分别设计行为与提示，不由一个模糊的通用“执行”按钮承包。当前 SQL 查询模式不阻止用户在 SSH/SFTP 终端执行其账号允许的操作。

## OTA 从第一版开始

与 macos-x 同类流程：Sparkle、GitHub Releases、仓库外 0600 文件中的独立 Ed25519 私钥、签名 feed、更新包先验签、用户确认安装。构建与发布、线上资产验证、实际安装三层分别记录。以后版本与 build 同时递增并核对 Bundle ID、执行文件、更新公钥与 feed。应用使用 ad-hoc 完整性签名；OTA 来源认证依赖 Ed25519，不声称具有固定证书身份。不会改写 macos-x 的更新源、密钥和已安装应用。

长期迭代先落实 [性能边界与兼容契约](PERFORMANCE_COMPATIBILITY.md) 中的 P0 项，再扩展模块覆盖；现有行数/字节上限与 CI 通过不能替代真实极端场景验收。
