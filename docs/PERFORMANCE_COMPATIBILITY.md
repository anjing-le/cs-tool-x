# 性能边界、兼容性与依赖来源

核对日期：2026-11-14。以下区分当前代码、已有验证和待做工作；不把库支持或参数上限写成整机性能保证。

## 驱动如何分发

当前不是 JDBC 下载管理器。SQLx/redis-rs/Reqwest 编译进 Rust 引擎，随签名应用和 OTA 一起升级；运行时不单独下载驱动、不执行远端驱动脚本。驱动库版本与数据库服务端版本分别记录，同一库可以服务多个协议兼容的服务端版本，但应用自身的 SQL、认证、TLS 和元数据接口仍可能不兼容。

实际版本以锁文件和生成清单为准；下表仅是核对日期的快照，不是第二份版本真相。清单覆盖关键组件，不是完整 SBOM 或漏洞扫描：

```sh
python3 tools/dependency-inventory.py
```

| 组件 | 当前锁定版本 | 上游及来源 | 应用验证范围 |
| --- | --- | --- | --- |
| MySQL/PG | sqlx / sqlx-mysql / sqlx-postgres 0.8.6 | https://github.com/launchbadge/sqlx；Cargo crates.io 索引及包校验和 | 本机 MySQL 9.6.0 / PostgreSQL 16.11 的隔离查询测试；不能外推到全部版本 |
| Redis | redis-rs 0.32.7 | https://github.com/redis-rs/redis-rs；Cargo 同上 | 本机 Redis 8.0.2；Standalone 路径，Cluster/Sentinel 未验收 |
| ES HTTP | Reqwest 0.12.28 | https://github.com/seanmonstar/reqwest；Cargo 同上 | 仅协议模拟；不等同于 Elasticsearch 任一服务端版本验收，也未宣称 OpenSearch 兼容 |
| 异步执行 | Tokio 1.54.1 | https://github.com/tokio-rs/tokio；Cargo 同上 | 进程协议与有界任务检查 |
| PTY/终端 | SwiftTerm 1.20.0，提交见 Package.resolved | https://github.com/migueldeicaza/SwiftTerm | 本地交互、分屏与关闭检查；没有本应用超大输出基准结论 |
| OTA | Sparkle 2.10.0，提交见 Package.resolved | https://github.com/sparkle-project/Sparkle | 发布资产签名验证；完整 OTA 安装不由此推定 |

Cargo.lock 包含 registry 来源、版本、checksum；Package.resolved 包含 Git URL、版本、提交。构建与 CI 使用 Cargo --locked 和 Swift --force-resolved-versions，解析发生漂移就失败，不静默升级。构建机器的外部包管理配置仍可能另行指定镜像，当前项目未搭建或承诺公司自维护镜像/备用下载站。源失效或验签失败不得静默改为不受信任来源。

版本/来源清单已接入 CI 输出，不代表已经做了漏洞数据库扫描、自动上游跟踪或按版本的完整服务端集成矩阵。这些当前均未配置为持续维护服务。

升级流程：显式修改依赖与 lockfile → 查看上游变更、安全公告、许可证 → 新旧版本协议/认证/TLS/类型/取消回归 → 性能前后对比 → 签名发布，保留上版 ZIP 和变更记录。不得自动追 latest 或让终端用户自行下载未校验插件。库不能兼容的历史版本应明确标记不支持，确有需求再评估隔离适配器，不能默认降低 TLS 校验。

## 服务端版本不能靠驱动版本代替

当前没有完整的服务端版本探测/能力矩阵。接下来连接时应获取服务端版本和所需能力，权限不允许获取时显示未知，不能让 INFO 等辅助探测破坏本来可用的连接。不在连接时扫全库。

MySQL 执行路径目前直接设置 MAX_EXECUTION_TIME，并使用只读事务。该变量有版本与产品差异：驱动支持 MySQL/MariaDB 不等于应用可无差别执行相同 SQL。兼容性需分别覆盖 MySQL 5.7/8.0/8.4/9.x、认证插件和 TLS；此处是候选测试集合，不是已承诺支持的范围。PG、ES、Redis 同样以实际目标环境建立矩阵，不凭协议相似宣称兼容 MariaDB/TiDB/CockroachDB/OpenSearch/Valkey。

每个矩阵项必须记录：服务端确切版本、驱动/应用版本、部署模式、认证与 TLS、功能/类型覆盖、测试日期、通过项和已知限制。旧版本是否值得支持，按真实用户需求决定，而非默认全部兼容。

## 已有保护和实际边界

| 路径 | 当前代码 | 不可据此推断 |
| --- | --- | --- |
| 终端 | 每终端 2,000 行历史，UI 最多 4 标签×2 分屏；锁定 SwiftTerm 提交含约 4 MiB 高水位/1 MiB 低水位背压、128 KiB 读取和约 4ms 批次让出 | 不等于每次解析/每帧小于 4ms，不等于本应用整机内存有硬上限，也不证明大文件吞吐和取消延迟达标 |
| SQL | 流式读行，最多返回 500 行；单元格展示约 64 KiB，展示数据预算约 8 MiB；每池最多 2 连接；只读事务及服务端超时设置 | 大 BLOB/长行可能先完整到达驱动；500 行不等于服务端只扫描 500 行；退出流/rollback 不等于服务端立即取消或网络不再接收 |
| ES | HTTP 流式响应体收集上限 8 MiB，搜索 size 上限 500 | JSON 解码、克隆和展示另有内存开销；聚合、查询本身仍可能昂贵 |
| Redis | SCAN COUNT 100；string 使用 GETRANGE 0..65535；集合/列表有限项预览；展示预算 | COUNT 只是提示；LRANGE/ZRANGE 的每个元素及 HSCAN 值仍可能很大，驱动解码在展示截断之前，不能宣称接收字节硬有界 |
| 引擎/RPC | 最多 4 并行任务、有界请求/回复通道；请求 256 KiB，回复序列化后最多 16 MiB；Swift 最多 8 pending、接收累计约 17 MiB | 上限不是整个进程 RSS；序列化/解码可能同时保留多份数据；数据会话最多 4 当前主要由 UI 限制，引擎本身还需准入硬上限 |
| 超时 | 连接约 12s，引擎查询约 20s，Swift 等待约 25s；SQL 服务端设置约 15s | 超时不是服务端已取消；事务回滚、连接复用、过期结果和断线仍需单独验收 |

## 大文件与持续日志规则

- 原始终端是命令通道。cat 大文件必然读取并传输全部内容，不能宣传客户端能消除其网络/磁盘成本，也不偷偷改写用户输入的 cat/tail 命令。
- 终端靠有限队列、PTY 背压、分批解析/绘制、有限历史保持可取消。不得把每个输出块无界排队到主线程，不得整段拼接后一次性渲染；不能为提速任意丢原始 ANSI 字节而破坏终端状态。
- 未来文件/日志预览走单独的范围读取：先 stat，再按 offset/length 获取末尾有限字节，再切行/解码。不能先下载全文件再 substring。仅 tail -n N 也不够：一个超长无换行文件仍可能导致大范围扫描，必须同时限制字节/时间。
- 文件预览需要 UTF-8 边界、不完整行/截断标记、二进制识别、文件变化和取消。持续跟踪需处理日志轮转/截断、断线、隐藏标签、缓慢消费者与停止。图形化预览当前尚未实现，SFTP 控制台不能算作已完成。
- 不借助无界磁盘缓存掩盖内存问题。日志落盘/会话录制若后续加入，必须有明确用户入口、空间预算与清理策略。

## 后续优先级与验收

先完成边界基线，再扩展更多工具模块。以下未标为通过：

1. P0：引擎独立限制会话准入；明确单行/单值与协议解码预算，巨大值安全失败时关闭/重建受影响连接，验收失败后能继续使用；客户端超时/取消与服务端真实状态明确分开。
2. P0：终端真实洪峰与中断测试；服务端版本/能力探测和第一份真实兼容矩阵。不要把单次 fixture 或模拟服务算成广泛支持。
3. P1：独立范围文件预览、增量日志跟踪；SQL 服务端分页/游标、受控导出与取消；Redis 大集合/超大值的安全预览策略。
4. P1：兼容版本矩阵 CI、上游公告/漏洞扫描流程、可回归性能报告；启用任何定期自动化另行明确配置，不能只写在文档里就说已维护。

压力用例：短行/10 MiB 单行、中文/拆分 UTF-8、ANSI/OSC、二进制、持续高吞吐、8 个窗格、慢网络/断线/反复开关；逻辑 1/10/100 GiB 文件的末尾读取与无换行尾部；大表、宽表、单值 1/64/256 MiB、昂贵 SELECT、取消/rollback/连接复用；Redis 巨大元素/哈希值与 SCAN 极端回复；ES 超限/深层 JSON。均在隔离环境和有磁盘/内存/时间预算的 fixture 上做，绝不默认冲击真实业务环境。稀疏文件与真实文件的测试结论分开。

每次记录应用/库/服务端版本、机器、release 构建、输入/吞吐、CPU、宿主与引擎 RSS 峰值/空闲恢复、UI 交互 p95、Ctrl-C/停止响应、句柄/线程/进程数。暂定普通交互 p95≤100ms、停止反馈≤200ms，属于待校准目标；资源应随队列/历史/会话预算收敛，而非随累计输出无限增长。尚无这些压力测试的实测结果，不能写“性能很好/任意大数据安全”。
