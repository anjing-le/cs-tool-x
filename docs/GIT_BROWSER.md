# Git 仓库浏览

首页第三个入口是 Git。打开目录后，左侧展示各仓库的当前分支及本地分支、远程分支、标签；中间展示按真实父关系绘制的彩色提交图、引用标签、提交信息、作者、日期、哈希；右侧显示所选提交说明及变更文件。选中的目录会保存在本机，下次进入恢复读取。

采用 [IDEA Git Log](https://www.jetbrains.com/help/idea/log-tab.html) 的三栏组织和标签含义：当前 HEAD 黄色、本地分支绿色、远程分支紫色，仓库使用稳定颜色条区分。外框及控件仍采用本项目的暖纸张/PaperControls。实现为独立 AppKit/ToolCore 代码，没有嵌入 IntelliJ Platform/JVM，没有复制 JetBrains 品牌资产，不声称逐像素等同于某个 IDEA 版本。源码调研包括 JetBrains 的 GraphCommitCellRenderer、LabelPainter、PrintElementGenerator；未移植其代码。

## 浏览与筛选

- 目录递归发现普通仓库、嵌套仓库、`.git` 文件形式的 worktree 和裸仓库。广度优先，先看到同级项目；不跟随子目录符号链接，不进入 `.git` 元数据或裸仓库对象目录。依赖目录里的真实仓库也在发现范围内，不静默排除。
- 默认选择第一个仓库；“所有仓库”按各仓库的拓扑顺序合并历史，始终区分仓库，即使提交哈希相同也不合并它们。
- 左侧文本筛选已读取的仓库路径、当前分支和分支名称。顶部仓库/分支/作者/日期和提交信息搜索通过 Git 查询历史，不只是筛选当前页面。提交搜索涵盖正文；7…64 位十六进制搜索按哈希定位，哈希定位不受分支筛选约束。
- 单击分支只筛选历史，不切换工作分支。选中提交读取其说明和文件列表；合并提交的文件相对第一父提交。文件名中的换行在列表显示为 `↵`。
- 远程分支是本机最后一次 fetch 后的记录，工具不联网 fetch，不声称远端实时状态。页面不会自动轮询；手动刷新重新读取目录和引用。

## 只读边界与性能预算

| 范围 | 当前实现 |
| --- | --- |
| 发现目录 | 最多 250,000 个条目、500 个仓库、20,000 个待遍历目录；条目间检查 20 秒时间预算和取消 |
| 仓库元数据 | 每仓库最多 5,000 个引用，整次最多 20,000 个；普通分支通常一次 for-each-ref 即读取 HEAD 和引用；Detached/空仓库额外读取 HEAD |
| 并发与时间 | 每批最多 4 个仓库并发；分支批量及历史批量各有 30 秒预算，每条 Git 命令最多 12 秒，批量剩余预算更少时缩短 |
| 输出 | 引用最多 8 MiB；日志 4 MiB；提交说明 256 KiB、文件列表 1 MiB；超限终止读取并显示失败，不能把残缺协议当完整结果 |
| 提交历史 | 单仓库每页最多 200 条，整页缓存最多 2,000 条；多仓库共享总预算，继续加载或缩小范围；不一次读取全部历史 |
| 图形与控件 | 提交图准备在后台；最多 64 条并行轨道，超出显示提示；表格复用行视图，下拉最多 200 个快捷分支，完整引用从左侧筛选 |
| 详情 | 最多 1,000 个变更路径、64,000 个展示字符；更多内容标记截断，不读取文件内容或执行 diff 转换 |

目录时间预算在文件系统调用之间检查；阻塞的网络盘或系统文件读取不保证在该秒数内中断。Git 子进程取消会终止本地进程并有强制结束兜底；离开模块、切换目录、改变查询都会取消旧任务并拒绝过期回调。不是对任意恶意仓库/文件系统的系统级沙箱或严格内存证明。

命令固定使用本机 `/usr/bin/git`，参数数组传递，不经 shell。禁用可选锁、终端认证提示、文件监视钩子及外部 diff/textconv，清除继承的 GIT_* 重定向环境；不运行 fetch、checkout、commit、reset 或 index/status 刷新。显式设置 GIT_NO_LAZY_FETCH=1 并禁用传输协议；部分克隆缺对象时显示失败，不自动下载。相关行为依据 [Git 环境变量文档](https://git-scm.com/docs/git)。不开后台服务，不引入新客户端。仍需要本机 Git/Command Line Tools 可用。

筛选或分页时未加载的父提交作为未闭合关系保留，不编造跳过历史的连线；颜色是视觉辅助，引用名、仓库名、哈希和文本状态提供对应信息。仓库读取失败、目录预算、引用预算、图线预算分别提示，不把“部分完成”写成“所有仓库都成功”。

CLI 的 git scan/refs/log/show 与 GUI 共用 ToolCore，具体输入、输出和限制以安装版本的 `schema` 为准；没有 Git 写命令。
